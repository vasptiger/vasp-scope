# 补丁流程（硬规矩）

> 起因：同一个会话里，我在 **pwsh 命令行内联拼代码补丁** 这件事上踩了 **6 次以上** 同一个坑 ✗
> （双引号串里出现 ASCII `"` → 截断；单引号串里 `\'` 不是转义；`$(...)`/`$var` 被展开；`<` 是重定向；
> `.Replace(a,b,1)` 是 C# 风格、.NET 没有这个重载 → **静默没生效**）。
> 结论：**靠"记住"没用** ✗，要靠**把危险做法从流程里删掉** ✓。

## 规矩（从 2026-10-12 起执行）

1. **代码/文档改动一律走 `write` / `edit` 工具** ✓ —— 它们不经过 shell，**没有任何引号/展开语义** ✓。
2. **批量文本替换走 `node tools/patch.mjs <patch.json>`** ✓ —— patch.json 也用 `write` 工具生成 ✓。
   - **禁止**：`$t=$t.Replace("…","…")` 这类把代码当 shell 字符串拼的写法 ✗（历史事故全来自这里 ✓）
   - **禁止**：在 pwsh 里写 `\'`、"…\"…\"" 这类跨语言转义 ✗
3. **每条 find 必须带 `expect` 计数** ✓；改动后必须带 `after` 事后计数 ✓。
   - 原因：`.Replace(a,b,1)` 那次，脚本自己打印 `ok 3/4/5` ✓ 而文件**一个字节都没变** ✗
     —— 我是靠"数出现次数"才抓住的 ✓（`LIVE.switching` 只有 1 处、应 4 ✗）。
4. **全有或全无** ✓：任一条 expect 不符 → 一个文件都不写 ✓（patch.mjs 已实现 ✓）。
5. **换行风格继承原文件** ✓：面板是 CRLF ✓、文档是 LF ✓ —— 绝不全局换成一种 ✗。
6. 特殊字符（如 `⇄` U+21C4）在 JSON 里**用转义写** ✓（`\u21c4`），避免任何编码环节 ✗。

## 两个工具的分工

| 场景 | 用什么 |
|---|---|
| 新建文件、重写整段代码 | `write` 工具 ✓ |
| 精确替换几处（±若干行） | `edit` 工具 ✓（天然要求"匹配唯一"✓） |
| **批量/多文件替换 + 计数验收** | `node tools/patch.mjs <patch.json>` ✓ |
| 只想知道"现状对不对" | `patch.mjs` 且 op 里**省略 replace** = verify-only ✓ |

## 示例：verify-only（只校验，不写盘）

```json
{ "ops": [
  { "file": "D:/dsh/vasp-panel.html", "find": "LIVE.switching", "expect": 4 },
  { "file": "D:/dsh/vasp-panel.html", "find": "\u21c4",         "expect": 0 }
] }
```
```
$ node tools/patch.mjs tools/verify-panel-state.json
  ✓ [1/4] vasp-panel.html 校验通过（出现 2 次）
  ...
  ✅ 全部通过；写入 0 个文件
```

## 示例：真改 + 事后验收

```json
{
  "ops": [
    { "file": "D:/dsh/vasp-panel.html", "find": "旧片段", "replace": "新片段", "expect": 1 }
  ],
  "after": [
    { "file": "D:/dsh/vasp-panel.html", "contains": "新片段", "count": 1 }
  ]
}
```
